Git은 어떻게 동작할까

Git은 프로젝트 폴더의 사진을 찍어 순서대로 보관하는 도구입니다. 사진을 어디에 두고, 어떻게 잇고, 어떻게 합치는지를 그림으로 따라가 봅니다.

예시 커밋은 tokkikim/Cursor-test 저장소의 실제 기록입니다. 파일을 모두 지운 뒤 PR #8로 main에 병합했습니다.

main 브랜치 작업 브랜치

01Git은 사진첩입니다

커밋(commit)은 그 순간 폴더 전체를 찍은 사진입니다. 새 사진을 찍어도 예전 사진은 지워지지 않고, 마지막 사진이 "빈 폴더"여도 앞의 사진들은 그대로 남습니다.

02파일이 머무는 네 공간

파일은 내 컴퓨터의 세 공간을 거쳐 GitHub로 갑니다. 명령어 하나가 화살표 하나에 해당합니다.

공간비유하는 일위치
작업 폴더책상 위지금 편집하고 있는 파일내 컴퓨터
스테이징 영역사진 찍을 자리에 세우기다음 커밋에 넣을 변경만 골라 두기내 컴퓨터
로컬 저장소내 앨범찍은 커밋을 모두 보관내 컴퓨터의 .git 폴더
원격 저장소공유 클라우드 앨범다른 사람과 같이 쓰는 앨범GitHub

03파일의 상태 변화

Git은 파일마다 지금 어느 단계에 있는지 기억합니다. git status가 보여 주는 것이 바로 이 상태입니다.

상태뜻git status --short 표시
UntrackedGit이 아직 모르는 새 파일??
Modified고쳤지만 아직 스테이징하지 않음 M (오른쪽 칸)
Staged다음 커밋에 들어가도록 준비됨M A D (왼쪽 칸)
Unmodified마지막 커밋과 똑같음표시 없음

04커밋은 부모를 가리킵니다

커밋마다 바로 앞 커밋(부모)의 ID가 적혀 있습니다. 그래서 커밋들은 최신에서 처음까지 거꾸로 이어진 사슬이 됩니다.

커밋에 들어 있는 것이 저장소의 예 (5b94983)
스냅샷그 순간의 전체 파일 상태 (여기서는 빈 폴더)
작성자, 시간작성자 정보와 2026-10-31 시각
메시지Remove all files from repository
부모 커밋69cd093
해시 (ID)위 내용 전체로 계산한 지문 5b949832…

내용이 한 글자만 바뀌어도 해시가 완전히 달라집니다. 부모 해시도 내용에 포함되므로, 과거 커밋 하나를 고치면 그 뒤의 모든 해시가 바뀝니다. 그래서 기록을 몰래 바꿀 수 없습니다.

05브랜치는 책갈피입니다

브랜치는 파일을 복사한 사본이 아니라 커밋 하나를 가리키는 이름표입니다. HEAD는 "지금 내가 서 있는 브랜치"를 뜻합니다. 이 저장소에서 실제로 일어난 일을 단계별로 보세요.

06병합하는 세 가지 방법

GitHub의 병합 버튼에는 세 가지 방식이 있습니다. 위 줄이 main, 아래 줄이 작업 브랜치(X, Y 커밋)입니다. 이번 PR #8은 merge 방식을 썼습니다.

방식결과 모양장점주의할 점
merge갈래가 합쳐지는 모양기록이 있는 그대로 남음병합 커밋이 늘어 기록이 복잡해 보일 수 있음
squash커밋 하나로 압축PR 하나 = 커밋 하나로 깔끔함작업 중 세부 커밋은 main에 남지 않음
rebase일직선읽기 쉬운 한 줄 기록커밋 해시가 새로 만들어짐

07내 컴퓨터와 GitHub 맞추기

로컬 저장소와 GitHub는 따로 있는 두 앨범입니다. 자동으로 맞춰지지 않으므로 명령어로 주고받습니다.

명령방향하는 일
git cloneGitHub → 내 컴퓨터저장소 전체를 모든 기록과 함께 처음 복사해 옴
git push내 컴퓨터 → GitHub내 커밋을 올리고 원격 브랜치 책갈피를 옮김
git fetchGitHub → 내 컴퓨터새 커밋을 받아만 둠. 내 브랜치와 파일은 그대로
git pullGitHub → 내 컴퓨터fetch한 뒤 내 브랜치에 합침

GitHub에서 PR #8을 병합해도 내 컴퓨터의 main은 그대로입니다. git pull origin main을 해야 내 컴퓨터에도 반영됩니다.

08다 지웠는데 왜 되돌릴 수 있을까

삭제도 결국 "빈 사진을 한 장 더 찍은 것"입니다. 파일이 있던 69cd093은 .git 안에 그대로 있습니다. 되돌리는 방법은 두 가지입니다.

방법원리이 저장소에서 쓰는 명령공유 브랜치
git revert반대 내용의 새 커밋을 추가git revert -m 1 e51f544권장
git reset브랜치 책갈피를 과거 커밋으로 이동git reset --hard 69cd093피하기

e51f544는 부모가 둘인 병합 커밋이라, 어느 쪽 부모를 기준으로 되돌릴지 정해야 합니다. -m 1은 첫 번째 부모(병합 전의 main, 즉 69cd093)를 기준으로 삼으라는 뜻입니다.

09.git 안을 들여다보면

매번 폴더 전체를 찍는데 용량이 크게 늘지 않는 이유는, 바뀌지 않은 파일은 이전 내용을 그대로 다시 가리키기 때문입니다.

객체역할
blob파일 내용. 이름 없이 내용만 저장하고, 내용이 같으면 같은 blob 하나를 씀
tree폴더 구조. 파일 이름과 blob, 하위 폴더(tree)를 연결
commit최상위 tree, 부모 커밋, 작성자, 메시지

Git, 사진첩으로 이해하기

어려운 용어는 잠시 접어 두고, 사진첩 하나만 떠올려 보세요. 여섯 장면을 차례로 따라가면 Git이 어떻게 움직이는지 자연스럽게 보여요. 각 장면은 다음 장면의 질문으로 끝나요.

장면 1 / 6

커밋은 사진 한 장이에요

Git은 프로젝트 폴더의 모습을 통째로 사진 찍어 앨범에 모아요. 이 사진 한 장을 커밋이라고 불러요.

새 사진을 찍어도 예전 사진은 지워지지 않아요. 마지막 사진이 텅 빈 폴더여도, 앞의 사진들은 앨범에 그대로 있어요.

한 줄 정리커밋 = 그 순간 폴더 전체를 찍은 사진

그럼 사진은 어떤 순서로 찍을까요?
장면 2 / 6

사진은 세 단계로 찍어요

책상 위에서 파일을 고치고, 사진에 넣을 것만 골라 촬영 자리에 세운 다음, 셔터를 눌러 앨범에 붙여요. 아래 버튼을 직접 눌러 보세요.

책상

작업 폴더 · 지금 고치는 파일

촬영 자리

스테이징 · 다음 사진에 넣을 것

앨범

저장소 · 찍은 사진 모음

README.md를 고쳤어요. 책상 위 파일에 "수정됨" 표시가 붙었죠? 이제 git add를 눌러 촬영 자리에 세워 보세요.

왜 촬영 자리를 한 번 더 거칠까요? 파일 10개를 고쳤어도 관련 있는 3개만 골라 사진 한 장에 담을 수 있게 하려는 거예요.

한 줄 정리git add로 고르고, git commit으로 찍어요

사진이 쌓이면 앨범은 어떻게 정리될까요?
장면 3 / 6

사진은 줄줄이 이어지고, 책갈피로 찾아요

새 사진에는 "내 바로 앞 사진은 이거야"라는 메모가 붙어요. 그래서 사진들이 한 줄로 이어져요.

브랜치는 그 줄 어딘가에 꽂아 둔 책갈피예요. 파일을 복사하는 게 아니라 이름표 하나만 붙이는 거라 아주 가벼워요. HEAD는 "지금 내가 펼쳐 보고 있는 책갈피"를 뜻해요.

한 줄 정리브랜치 = 사진 하나를 가리키는 책갈피

책갈피가 서로 다른 길로 가면, 다시 합칠 수 있을까요?

이 저장소에서 실제로 있었던 일로 볼게요. 버튼을 눌러 한 단계씩 넘겨 보세요.

한 줄 정리합치기(merge) = 두 갈래를 잇는 사진을 한 장 더 찍는 것

GitHub에서 합쳤는데, 내 컴퓨터에도 반영됐을까요?
장면 5 / 6

내 컴퓨터와 GitHub는 따로 있어요

앨범은 내 컴퓨터에 하나, GitHub에 하나 있어요. 저절로 똑같아지지 않아서 직접 주고받아야 해요. 그래서 GitHub에서 합친 결과는 아직 내 컴퓨터에 없어요.

git push내 사진을 GitHub에 올리기
git pullGitHub 사진을 받아서 내 앨범에 합치기
git fetch받아만 두고, 내 앨범은 그대로 두기
git clone앨범 전체를 처음 통째로 복사하기

한 줄 정리push로 올리고, pull로 받아요

마지막 질문. 다 지운 파일, 되살릴 수 있을까요?
장면 6 / 6

지운 것도 되돌릴 수 있어요

네, 가능해요. 삭제도 결국 "텅 빈 폴더 사진"을 한 장 더 찍은 것뿐이라, 파일이 있던 사진은 앨범에 그대로 있거든요.

되돌릴 때도 예전 사진을 지우지 않아요. 예전 모습 그대로인 새 사진을 한 장 더 찍어요. 이게 git revert예요.

git revert -m 1 e51f544

e51f544는 앞 사진이 두 장인 합치기 사진이라, 어느 쪽 모습으로 돌아갈지 정해 줘야 해요. -m 1은 첫 번째 앞 사진(원래 main, 69cd093)을 기준으로 하라는 뜻이에요.

git reset이라는 방법도 있어요. 책갈피를 뒤로 돌려서 그 뒤 사진을 기록에서 빼 버리는 방식이라, 이미 GitHub에 올린 기록에는 쓰지 않는 게 안전해요.

한 줄 정리revert = 지우지 않고, 되돌린 사진을 새로 찍기
